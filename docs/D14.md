## 1. Tujuan

Agen pembangun bekerja terhadap kontrak. Tanpa kontrak yang ditetapkan lebih dulu, setiap agen akan mengarang bentuk antarmukanya sendiri, dan penggabungannya menjadi pekerjaan perbaikan yang mahal.

Dokumen ini menetapkan bentuk kontrak, bukan seluruh isinya. Berkas OpenAPI lengkap dihasilkan dari kode dan disimpan di repositori; yang ditetapkan di sini adalah aturan yang mengikat berkas itu.

---

## 2. Prinsip Kontrak

**KT-01 — Kontrak ditulis sebelum implementasi, bukan dihasilkan darinya.**
Berkas OpenAPI awal disusun manusia sebagai bagian langkah `/plan` pada D-12. Setelah itu ia dihasilkan dari kode dan diperiksa terhadap versi awal.

**KT-02 — Perubahan yang merusak memerlukan versi baru.**
Antarmuka diawali `/api/v1`. Penambahan bidang bersifat aman; penghapusan, penggantian nama, dan perubahan makna tidak.

**KT-03 — Galat berbentuk seragam.**
Satu bentuk galat untuk seluruh antarmuka (Bagian 4).

**KT-04 — Antarmuka tidak pernah mengembalikan data pribadi mentah.**
Termasuk pada rute internal. Konsekuensi FR-B04 dan D-13 KD-14.

**KT-05 — Setiap rute menyatakan peran yang boleh mengaksesnya.**
Pemeriksaan dilakukan di lapisan layanan, bukan di antarmuka pengguna (KA-01).

**KT-06 — Setiap tanggapan jawaban membawa versi.**
Versi model, versi indeks, dan versi kode disertakan agar hasil dapat direproduksi (NFR-15).

## 4. Bentuk Tanggapan

### 4.1 Tanggapan Jawaban

Rute `/api/v1/tanya` adalah kontrak terpenting dalam sistem; ia menjadi tempat seluruh kendali D-07 dan D-13 bertemu.

```json
{
  "id_pesan": "msg_01H…",
  "status_dasar": "kuat | terbatas | tidak_ditemukan | di_luar_domain",
  "ringkasan_tindakan": ["…", "…"],
  "penjelasan": "…",
  "klaim": [
    { "teks": "…", "id_segmen": ["seg_…"], "peringkat_kepercayaan": "T1" }
  ],
  "sitasi": [
    {
      "id_dokumen": "doc_…",
      "judul": "Permendikdasmen Nomor 1 Tahun 2026",
      "penerbit": "…", "tahun": 2026,
      "bagian": "Pasal 7 ayat (2)",
      "status_keberlakuan": "berlaku | diubah | dicabut",
      "rujukan_pengganti": null,
      "tautan": "https://…"
    }
  ],
  "bacaan_lanjutan": [ { "judul": "…", "tautan": "…" } ],
  "penafian": "…",
  "versi": { "model": "…", "indeks": "…", "kode": "…" }
}
```

| Bidang | Aturan |
|---|---|
| `status_dasar` | Empat nilai saja; tidak ada angka probabilitas (FR-F06) |
| `klaim[].id_segmen` | Wajib tidak kosong; diperiksa validator VS-01 dan VS-02 |
| `klaim[].peringkat_kepercayaan` | T1 s.d. T4 (D-13 Bagian 6); klaim bersandar tunggal T3 atau T4 tidak boleh muncul di sini (FR-F15) |
| `bacaan_lanjutan` | Tempat satu-satunya bagi sumber `indeks_metadata`; tidak pernah menjadi dasar klaim (FR-D06) |
| `sitasi[].status_keberlakuan` | Wajib; nilai `dicabut` tidak boleh muncul (VS-06) |
| `versi` | Wajib pada setiap tanggapan (KT-06) |

Keadaan `tidak_ditemukan` dan `di_luar_domain` memakai bentuk yang sama dengan `ringkasan_tindakan` dan `klaim` kosong. Bentuk yang seragam inilah yang membuat layar D-05 dapat menampilkannya sebagai jawaban sah, bukan pesan galat.

### 4.2 Bentuk Galat

```json
{
  "galat": {
    "kode": "VALIDASI_GAGAL",
    "pesan_pengguna": "Ada gangguan di sistem kami. Yang Anda ketik sudah tersimpan.",
    "id_jejak": "trc_…"
  }
}
```

| Aturan | Keterangan |
|---|---|
| `pesan_pengguna` | Bahasa manusia, memenuhi NFR-19; tidak pernah memuat rincian teknis |
| `id_jejak` | Untuk penelusuran log; tidak bermakna bagi pengguna |
| Rincian teknis | Hanya ke log, tidak pernah ke tanggapan |

| Kode galat | Kapan |
|---|---|
| `TIDAK_TERAUTENTIKASI` | Sesi tidak sah |
| `TIDAK_BERWENANG` | Peran tidak mencukupi |
| `VALIDASI_GAGAL` | Masukan tidak memenuhi aturan |
| `SUMBER_TIDAK_ADA` | Id tidak ditemukan |
| `PAGU_TERLAMPAUI` | Pagu tayang atau pembatasan laju |
| `LAYANAN_MODEL_GAGAL` | Penyedia LLM tidak merespons |
| `GALAT_INTERNAL` | Selebihnya |

## 5. Kamus Data

Memperinci D-04 Bagian 7. Hanya bidang yang maknanya tidak terbaca dari namanya yang dijelaskan.

### 5.1 Bidang yang Sering Disalahpahami

| Tabel.bidang | Jenis | Makna dan aturan |
|---|---|---|
| `pengguna.pseudonim` | teks | Penanda untuk telemetri. **Pemetaan ke identitas berada di basis data terpisah** (KA-03) |
| `profil_sekolah.jalur_akreditasi` | enum | `visitasi` atau `automasi`. Memengaruhi pemicu kontekstual (D-02 Bagian 5) |
| `persetujuan.dicabut_pada` | waktu | Bila terisi, perekaman telemetri berhenti seketika (FR-J05) |
| `dokumen_sumber.status_anonimisasi` | enum | `menunggu`, `terverifikasi`, `ditolak`. Hanya `terverifikasi` yang boleh diindeks |
| `dokumen_sumber.area_simpan` | enum | `karantina` atau `korpus`. Kredensial berbeda; bukan sekadar penanda (ADR-06) |
| `dokumen_sumber.status_keberlakuan` | enum | `berlaku`, `diubah`, `dicabut` (KL-07) |
| `dokumen_sumber.lisensi` | teks | Kosong berarti tidak dapat tayang (KL-02) |
| `segmen_teks.peringkat_kepercayaan` | enum | T1 s.d. T4 (D-13 Bagian 6) |
| `segmen_teks.indeks_tujuan` | enum | `utama` atau `metadata`. Menentukan boleh tidaknya masuk konteks LLM (FR-D06) |
| `segmen_teks.penanda_bagian` | teks | Pasal, ayat, atau subjudul. **Wajib**; tanpanya FR-F11 gagal |
| `anotasi_entitas.mulai_karakter` | bilangan | **Indeks karakter, bukan token** (D-03 Bagian 15) |
| `anotasi.versi_skema` | teks | Wajib; memungkinkan pemisahan korpus bila skema naik versi (FR-C08) |
| `anotasi.status_pra_anotasi` | enum | `manual`, `pra_anotasi_dikoreksi`. Diperlukan untuk pengendalian *automation bias* (FR-C10) |
| `butir_pengetahuan.alasan_relevansi` | teks | Satu kalimat, menyebut ciri konkret sekolah pengguna (D-06 Bagian 5) |
| `komitmen.status` | enum | `diterapkan`, `berjalan`, `belum`, `tidak_jadi`. **Empat nilai setara**; tidak ada hierarki (PK-06) |
| `peristiwa.properti` | JSONB | Isinya mengikuti taksonomi D-01 Bagian 9; tidak pernah memuat data pribadi |

### 5.2 Aturan Lintas Bidang

| Kode | Aturan |
|---|---|
| KM-01 | Seluruh waktu disimpan dalam UTC; penyajian mengikuti zona waktu pengguna |
| KM-02 | Penghapusan bersifat lunak untuk data penelitian, keras untuk permintaan penarikan data (NFR-09) |
| KM-03 | Tidak ada bidang teks bebas yang menyimpan data pribadi tanpa melewati penyamaran |
| KM-04 | Enum tidak pernah menyimpan nilai di luar daftar; perubahan daftar adalah perubahan versi |

## 6. Aturan bagi Agen Pembangun

Melengkapi konstitusi D-12 Bagian 2.

| Kode | Aturan |
|---|---|
| AG-01 | Agen tidak boleh mengubah bentuk tanggapan tanpa persetujuan manusia |
| AG-02 | Agen tidak boleh menambah rute yang tidak ada pada Bagian 3 |
| AG-03 | Agen tidak boleh menambah bidang pada tanggapan `/tanya`; bentuknya adalah kontrak kepatuhan, bukan kenyamanan |
| AG-04 | Agen tidak boleh mengubah daftar nilai enum |
| AG-05 | Setiap rute baru wajib menyatakan peran yang mengaksesnya dan diuji sebagai UK-15 |

AG-03 diberi penekanan karena bentuk tanggapan `/tanya` adalah tempat FR-D06, FR-F15, VS-04, dan VS-06 diwujudkan. Menambahkan bidang di sana berpotensi membuka jalur yang tidak diperiksa validator.
